# 前端页面开发计划（每 Agent 展示面）

配套文档：《前端页面设计.md》。本文只规划内置静态站点与 Agent 增量页面，不改变节点协议、存储和工单语义。

状态：**已完成（2026-11-15）**。

> W0–W5 全部落地：`go test -race ./...` 全绿，`scripts/e2e-ui.sh` 通过；
> `e2e.sh`、`e2e-wake.sh`、compose demo 回归通过。
> 与计划的差异：待处理阈值写死为重试 5 次 / 滞留 10 分钟；其余按计划实现。

## 1. 交付目标

节点启动后，本机浏览器打开 `http://127.0.0.1:7878/` 可以：

- 看到自身信息、状态汇总、待处理项、名录、工单列表；
- 发起一张工单；
- 查看工单详情、事件流、回执，并下载交付物；
- 看到 Agent 在 `pages/` 下新增的页面链接，点击可跳转。

验收以设计文档第 13 节为准。

## 2. 范围

**做**

| 模块 | 内容 |
|---|---|
| 配置 | `ui.listen`（默认 `127.0.0.1:7878`，空值关闭）、`ui.root`（默认 `data/www`）；启动硬校验 loopback |
| 静态骨架 | 首次启动创建 `root/pages/`、说明文件与示例页 |
| 内置页面 | 主页面、发起工单页、工单详情页；脚本样式放 `/_ui/` |
| Agent 页面 | `pages/` 自动发现、标题解析、按时间倒序、自动生成链接 |
| 数据接口 | `node`、`status`、`peers`（脱敏）、`tickets`、`tickets/{id}`、`tickets/{id}/artifacts`、`pages`、`blobs/{hash}` |
| 写接口 | `POST /api/tickets`（唯一写操作） |
| 安全 | Host / Origin、JSON Content-Type、`no-store`、按路径区分的 CSP、路径与符号链接限制 |
| 测试 | 脱敏、跨源、启动校验、页面发现、下载头、发起工单、原有 e2e 回归 |
| 文档 | README 页面入口与容器映射；compose 注释端口与 `pages` 挂载 |

**不做**

- 跨机器访问、鉴权、token、HTTPS。
- 动态配置修改（bootstrap、allow_from、wake 只展示）。
- **用户提交 / inbox / 上传：不在范围内，所有提交都由 Agent 完成。**
- 交付物内联预览。
- Agent 覆盖内置主页面。
- 外部 CDN 与外部资源。
- 多节点总入口、SSE / WebSocket。

## 4. 里程碑

单人、熟悉现有代码，合计约 **4 人日**。

### W0 · 配置与静态骨架（0.5 天）

- `UIConfig{Listen, Root}`：默认 `127.0.0.1:7878`、`data/www`；`listen` 为空则不启动 UI。
- loopback 校验：`127.0.0.1`、`::1`、`localhost` 通过；`0.0.0.0`、`::`、其他地址直接报错退出。
- 首次启动创建 `root/pages/`，写入 `README.md`（Agent 约定）与 `example.html` / `example.json`。
- `webui` 骨架：先返回一个占位主页和 `/api/node`。
- `/api/node` 与控制面 `/node` 都补上 `version`。
- 测试：非 loopback 拒绝启动；空值不监听；`/api/node` 含版本。

**完成标志**：`curl http://127.0.0.1:7878/api/node` 返回自身信息与版本；`ui.listen` 配成 `0.0.0.0` 启动失败。

### W1 · 数据接口（1 天）

- `/api/status`：工单计数（运行/完成/作废）、跳计数、outbox 深度，以及待处理项。
- 待处理规则（常量，先写死）：
  - `hop_rejected` / `hop_expired` → 建议 `redispatch` 或 `void`；
  - `outbox_stuck`：重试 ≥ 5 次或滞留 > 10 分钟 → 建议检查对方可达性；
  - 每项带 ticket、hop、peer、age、hint（可复制命令）。
- `/api/peers`：服务端脱敏，剔除 `pubkey`、`wake.host_fp`、`wake.target`、`wake.container`。
- `/api/tickets`、`/api/tickets/{id}`：状态、事件、回执；不存在返回 404。
- `POST /api/tickets`：名称解析与 `CreateReq.Validate` 复用现有逻辑。
- 测试：脱敏字段不出现；创建后 CLI 可见；404；待处理规则命中。

**完成标志**：用 curl 能完成“看状态 → 看名录 → 发单 → 看详情”全流程。

### W2 · 页面发现与交付物（0.5 天）

- `/api/pages`：递归扫描 `root/pages`，忽略 `_`/`.` 开头；标题优先级：同名 `.json` 的 `title` → `<title>` → 文件名；按修改时间倒序。
- `/pages/*` 静态服务：只暴露 `root/pages`，拒绝符号链接、`..`、点文件；按扩展名给 Content-Type。
- `/api/tickets/{id}/artifacts`：按工单从 receipts 桶汇总，返回跳号、blob、大小、时间、下载地址。
- `/api/blobs/{hash}`：校验哈希，流式输出；`application/octet-stream` + `Content-Disposition: attachment` + `nosniff`。
- 测试：新增文件后 `/api/pages` 出现；`_` 开头不出现；符号链接与 `..` 被拒；下载头正确。

**完成标志**：放一个 `pages/hello.html`，接口立刻列出；工单详情能下载交付物。

### W3 · 内置页面（1 天）

- 主页面：自身信息、bootstrap 数量、状态汇总、待处理（含可复制命令）、名录、工单列表、Agent 页面链接。
- `/new.html`：名录多选（顺序即流转）、JSON 表单、提交后跳转详情。
- `/ticket.html?id=`：每跳状态、事件流、回执、交付物下载。
- 全部动态内容用 `textContent` / `createTextNode`；不拼 `innerHTML`。
- 轮询 2 秒，页面不可见时暂停。
- 内置页 CSP：`script-src 'self'`，脚本全部放 `/_ui/app.js`；Agent 页按设计第 9 节 B 方案。

**完成标志**：浏览器里完成看板与发单；含 `<script>` 的描述显示为文本。

### W4 · 安全收口（0.5 天）

- Host 白名单：`127.0.0.1:<port>`、`localhost:<port>`、`[::1]:<port>`，其余 403。
- 写请求 Origin 校验；`Content-Type: application/json` 才接受。
- 所有页面与 API：`Cache-Control: no-store`。
- CSP 按路径注入；`X-Content-Type-Options: nosniff`、`frame-ancestors 'none'`。
- 测试覆盖每一条。

**完成标志**：`Host: evil.example` 403；跨源 POST 被拒；响应头符合设计。

### W5 · 冒烟与文档（0.5 天）

- `scripts/e2e-ui.sh`：
  1. 启动节点；
  2. 断言 `/` 可访问、`/api/peers` 中无密钥字段；
  3. 放一个 `pages/hello.html`，断言 `/api/pages` 含它；
  4. 通过 `/api/tickets` 创建工单，断言列表可见；
  5. 断言 `/api/tickets/{id}` 返回事件。
- README：页面入口、`pages/` 约定、容器端口与挂载方式、禁止 `-p 7878:7878`。
- compose：注释掉的 `127.0.0.1:7878:7878` 与 `./www/pages:/data/www/pages`。
- 回归：`go test -race ./...`、`e2e.sh`、`e2e-wake.sh`、compose demo。

**完成标志**：`e2e-ui.sh` 通过；README 三步能打开页面。

## 5. 排序理由

- **W0 先立配置与安全校验**：loopback 与关闭开关是最容易埋坑的地方。
- **W1 数据先于页面**：状态与名录接口独立可用，页面只是消费者。
- **W2 页面发现与下载先于视图**：确认“加文件即链接”和“能拿到文件”两条主线。
- **W3 集中写页面**：接口稳定后一次写完，避免边改接口边改页面。
- **W4 安全单独一步**：不因赶页面而跳过。
- **W5 用 curl 冒烟**：不引入浏览器自动化。

## 6. 测试策略

| 层 | 手段 | 覆盖 |
|---|---|---|
| 单元 | `httptest` + 临时数据目录 | 脱敏、Host/Origin、Content-Type、404、创建校验 |
| 文件 | 临时 `pages/` | 发现规则、标题解析、符号链接与路径穿越 |
| 安全 | 同上层 | 非 loopback 拒绝、CSP 头、no-store、下载头 |
| 冒烟 | `scripts/e2e-ui.sh` | 页面、名录、页面发现、发单、详情 |
| 回归 | `go test -race ./...` 与三个既有 e2e | 原有功能不受影响 |

不引入浏览器自动化；页面渲染的人工检查放在 W3 完成标志。

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 监听误配 `0.0.0.0` | 无鉴权控制面暴露到内网 | 启动硬校验 loopback，测试覆盖 |
| 脱敏只做在前端 | 密钥字段仍下发浏览器 | 服务端裁剪，断言响应体 |
| 符号链接逃逸 | 通过页面读到数据目录外文件 | 静态层拒绝符号链接，测试覆盖 |
| Agent 页面渲染不再转义 | 本机浏览器 XSS | CSP 限制外发；`pages/README.md` 写明责任 |
| 待处理规则误报 | 页面噪声 | 阈值写死为常量，先观察再调整 |
| 页面数量增长导致列表变长 | 主页面难用 | 按时间倒序；后续再加分组或分页 |
| 范围蔓延（提交、预览、鉴权） | 工期翻倍 | 第 2 节“不做”清单为防线 |

## 8. 验收

与设计文档第 13 节一致，逐条在 `scripts/e2e-ui.sh` 或人工浏览器检查中覆盖：

1. 主页面显示自身信息、名录、工单、待处理。
2. 新增 `pages/hello.html` 后链接自动出现并可打开。
3. 页面与接口都不含 `pubkey`、`wake.target`、`wake.container`、`host_fp`。
4. 通过页面发起工单，CLI 可见。
5. 详情页能下载交付物，响应头为 attachment。
6. `ui.listen=0.0.0.0:7878` 时节点拒绝启动。
7. 网络面 `:8787/` 仍返回 404。
8. Agent 页可运行内联脚本；CSP 含 `connect-src 'self'`；内置页不含 `'unsafe-inline'`。
