# 前端页面设计（每 Agent 的展示面）

状态：**已实现（2026-11-15）**。本机访问、配置只展示不修改、用户提交不在范围内、多页面增量扩展、HTML 自由度取方案 B。

## 1. 定位

每个节点自带一个**静态站点**，面向本机浏览器：

- 主页面是内置的默认模板，展示节点自身、名录、工单、待处理事项；
- Agent 通过**新增页面**来扩展展示，新增的页面自动出现在主页面的链接区；
- 不追求一个页面做所有事。工单详情、发起工单都是独立页面，Agent 的成果页也各自独立。

和之前的区别：不再把整个前端塞进一个 HTML，也不要求 Agent 改写主页面。**增量 = 往 `pages/` 里加文件。**

## 2. 已定决策

| 项 | 决定 |
|---|---|
| 访问范围 | 只监听本机 `127.0.0.1`，不做跨机器访问 |
| 鉴权 | v1 不做，前提是单用户主机 |
| 动态配置 | **只展示，不允许修改**（bootstrap、allow_from、wake 等） |
| 用户提交 | **不在范围内**：所有提交都由 Agent 完成，不提供人类上传入口 |
| 页面形态 | 多页面，内置主页面 + Agent 增量新增页面 |
| 主页面归属 | 内置模板，Agent 不可覆盖，只自动收集新增页面的链接 |
| 可选写操作 | 仅"发起工单"一个（沿用原需求） |

## 3. 访问与监听

```json
{"ui": {"listen": "127.0.0.1:7878", "root": "data/www"}}
```

- 默认 `127.0.0.1:7878`；`listen` 设为空字符串关闭 UI。
- **启动校验必须是 loopback**，填 `0.0.0.0` 直接报错退出。
- `root` 是 Agent 可写目录，默认 `data/www`，可挂载；首次启动自动创建 `root/pages/` 并放一份说明。
- 网络面 `0.0.0.0:8787` 不注册任何 UI 路由。
- 同机所有用户都能访问 loopback 端口；这是相对 Unix socket（0600）的退步，接受前提是单用户主机。

## 4. 页面模型

### 4.1 目录

```
data/www/
  pages/                     Agent 唯一可写的静态区
    README.md                约定说明（首次启动生成）
    example.html             示例页（可删）
    example.json             可选元数据 {"title": "...", "desc": "..."}
    report-2026-11-15.html
    assets/                  Agent 自己的 css/js/图片
```

内置页面不在磁盘上，直接从二进制内嵌资源提供，因此 Agent 无法破坏入口页。

### 4.2 内置页面

| 路径 | 作用 |
|---|---|
| `/` | 主页面：自身信息、状态汇总、待处理、名录、工单列表、Agent 页面链接 |
| `/new.html` | 发起工单 |
| `/ticket.html?id=<ticket>` | 工单详情：每跳状态、事件流、回执、交付物下载 |
| `/_ui/app.js`、`/_ui/style.css` | 内置页面的脚本与样式 |

### 4.3 Agent 页面与自动链接

- 放在 `pages/` 下的 `.html` 文件自动被发现，规则：
  - 忽略以 `_` 或 `.` 开头的文件；
  - 链接标题优先取同名 `.json` 的 `title`，其次取页面 `<title>`，最后用文件名；
  - 按文件修改时间倒序；
  - 支持子目录，链接使用相对路径。
- 主页面链接区显示为"Agent 发布的页面"，点击跳到 `/pages/<file>`。
- **Agent 不需要改主页面**：加文件即出现链接。这样没有合并冲突，也不会因为一次写坏把入口弄丢。
- 非 `.html` 文件（图片、css、js）按扩展名提供，供 Agent 页面引用。
- 建议 Agent 原子写入（临时文件 + rename），避免浏览器读到半截页面。

### 4.4 保留路径

`/api/*`、`/_ui/*`、`/pages/*` 由程序处理；`pages/` 之外的文件不对外提供，根目录不放可执行内容。

```
│ 工单 运行 2 · 完成 8 · 作废 0                                   │
│ 队列 outbox 0 条                                                │
├ 待处理 ─────────────────────────────────────────────────────────┤
│ hop_rejected  apple → peach 第2跳 2分钟  [改派命令] [作废命令]   │
├ 名录 ───────────────────────────────────────────────────────────┤
│ banana#a1b2 resident  https://10.0.0.1  发单节点                │
│ peach#c3d4  wakeable  https://10.0.0.3  写文档                  │
├ 我的工单 ───────────────────────────────────────────────────────┤

```

配置信息（bootstrap、allow_from、wake.mode、network）只展示，不可编辑。`wake` 只显示 mode，不显示 target / container / host_fp。

待处理项里的方括号是**可复制的 CLI 命令**，不是页面按钮；页面本身只做展示和发起工单，不改工单状态。

### 5.2 发起工单页

- 目标节点多选（来自名录），顺序即流转顺序；
- 表单为 JSON textarea，提交前本地校验；
- 提交后跳转到工单详情页。

### 5.3 工单详情页

- 每跳状态、完整事件流；
- 回执：跳号、blob 哈希、大小、时间、签名者；
- 交付物下载链接；
- 待处理项给出可复制的 CLI 命令（改派、作废），页面本身不改状态。

## 6. 接口

只挂在 UI 监听上：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/node` | 自身信息、版本、network、endpoint、bootstrap 数量 |
| GET | `/api/status` | 汇总、待处理项、outbox 深度 |
| GET | `/api/peers` | 脱敏名录 |
| GET | `/api/tickets` | 工单列表 |
| GET | `/api/tickets/{id}` | 状态、事件、回执 |
| GET | `/api/tickets/{id}/artifacts` | 交付物列表（blob、大小、跳号） |
| GET | `/api/pages` | 发现到的 Agent 页面与标题 |
| GET | `/api/blobs/{hash}` | 下载交付物 |
| POST | `/api/tickets` | 发起工单（唯一写接口） |

脱敏规则同前：`/api/peers` 剔除 `pubkey`、`wake.host_fp`、`wake.target`、`wake.container`。

## 7. 交付物下载

- `/api/blobs/{hash}` 一律 `Content-Type: application/octet-stream`、`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`。
- **不做同源内联预览**：交付物来自其他 Agent，若按 HTML/图片内联，会获得与页面相同的源和 API 访问权。Agent 想展示成果，可以在自己的页面里引用已确认安全的副本。
- 当前 blob 不保存原始文件名，下载名用 `<ticket>-hop<hop>-<hash 前 8 位>`。保存原始名需要改交付协议，列到后续版本。

## 8. 安全

| 项 | 做法 |
|---|---|
| 监听 | 强制 loopback，启动校验 |
| Host / Origin | 只接受 `127.0.0.1:<port>` / `localhost:<port>` / `[::1]:<port>`；写请求带 Origin 时必须同源 |
| CSRF | 写接口要求 `application/json`；跨站表单发不出该类型 |
| 缓存 | 页面与 API 全部 `Cache-Control: no-store` |
| 路径 | 静态区只暴露 `pages/`；拒绝符号链接、拒绝 `..`、拒绝点文件 |
| XSS（内置页） | 一律 `textContent`，不拼 `innerHTML` |
| XSS（Agent 页） | 由 Agent 负责；CSP 限制数据外发（见第 9 节） |
| 多用户主机 | v1 不设防，文档写清前提 |

## 9. HTML 自由度（已定：方案 B）

Agent 页面能用到什么程度，直接决定 CSP 和 XSS 的责任划分。

| 方案 | 允许 | 好处 | 代价 |
|---|---|---|---|
| A 严格 | 只有静态 HTML/CSS，脚本必须是同源 `.js` 文件，禁用内联 | CSP 可以做到很紧 | LLM 写多文件容易出错；自包含能力差 |
| **B（采用）** | 允许内联 `<script>` / `<style>`，禁止外部资源 | 单文件自包含，Agent 写起来最自然；图表可用内联 SVG/Canvas | XSS 面变大，靠 CSP 限制外发 |
| C 完全自由 | 无 CSP，允许外部 CDN | 最灵活 | 数据可被外链带出；内网无外网时页面不可用 |

**采用的策略按路径区分：**

- **内置页面**（`/`、`/new.html`、`/ticket.html`）：`script-src 'self'`，全部脚本放在 `/_ui/app.js`，不允许内联。入口页的 XSS 面最小。
- **Agent 页面**（`/pages/*`）：方案 B，允许内联脚本与样式，CSP 收紧到"只能访问自己"。

Agent 页面的 CSP：

```
default-src 'none';
script-src 'self' 'unsafe-inline';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self' data:;
media-src 'self';
connect-src 'self';
form-action 'self';
frame-ancestors 'none';
base-uri 'none';
object-src 'none';
```

这套规则的实际含义：

- Agent 可以写自包含页面，内联脚本、内联样式都行；
- 但**不能**通过 `fetch`/`XHR`/`WebSocket` 把数据发到外部（`connect-src 'self'`）；
- **不能**用外部图片、字体、CDN 做外带（`img-src`/`font-src` 限 self）；
- **不能**用表单提交到外部（`form-action 'self'`）；
- 外部 CDN 不可用，页面必须自带资源——内网环境反而更可靠。

仍未覆盖的风险：Agent 页面渲染其他 Agent 塞进来的内容时若不做转义，脚本会在本机浏览器里执行，能读本页同源的 API。缓解手段是默认模板提供转义函数、在 `pages/README.md` 里写清责任；根本方案是让交付物/名录数据以纯文本传递。

**已接受的约束**：外部 CDN 一律不可用，页面必须自带资源。内网环境这反而是优点——离线也能打开。

## 10. 本次不做

- 跨机器访问、鉴权、token、HTTPS。
- 动态配置修改（bootstrap、allow_from、wake 等只能展示）。
- 用户提交 / inbox / 上传。**不在范围内，不是延期**：所有提交都由 Agent 完成。
- 交付物内联预览。
- Agent 覆盖主页面。
- 外部 CDN 与外部资源。
- 多节点总入口（fleet 页面）。
- SSE / WebSocket 推送（2 秒轮询）。

## 11. 容器访问

| 方式 | 命令 | 说明 |
|---|---|---|
| 端口映射（推荐） | `-p 127.0.0.1:7878:7878` | 只发布到宿主机回环 |
| SSH 隧道 | `ssh -L 7878:127.0.0.1:7878 host` | 远程机器 |
| **禁止** | `-p 7878:7878` | 暴露到内网，无鉴权 |

`pages/` 建议挂载出来，Agent 在容器内写文件，宿主机可以直接看到。

## 13. 验收

1. 浏览器打开 `http://127.0.0.1:7878/`，看到自身信息、名录、工单、待处理。
2. 往 `data/www/pages/` 放一个 `hello.html`，刷新主页面，链接自动出现，点击可打开。
3. 名录接口与页面上都没有 `pubkey`、`wake.target`、`wake.container`、`host_fp`。
4. 在 `/new.html` 发起工单，CLI `billgo ticket show` 能看到同一张工单。
5. 工单详情页能下载交付物，响应头是 attachment。
6. 把 `ui.listen` 改成 `0.0.0.0:7878`，节点拒绝启动。
7. `https://<节点>:8787/` 仍返回 404。
8. `/pages/` 下的页面可以运行内联脚本；响应头 CSP 含 `connect-src 'self'`；内置页响应头 CSP 不含 `'unsafe-inline'`。
