# billgo 手工测试指南

面向当前 `billgo:dev` 镜像的手工验收。容器部分覆盖 CLI、名录、工单闭环、拒绝/改派/作废、交付物下载、页面接口与持久化；宿主机部分用浏览器验收页面。

前置：

```bash
cd /Users/wanglei/code/agent/pi-docker/billgo
docker build -t billgo:dev .
```

> 当前镜像里的 CLI 还没有 `--json`，下面都用默认的人类输出。页面是容器里的 `billui`，默认只监听 `127.0.0.1:7878`。密码在 `docker logs` 和 `/data/billui.password`。

## 1. 单节点冒烟

```bash
mkdir -p /tmp/billgo-lab/data
cat >/tmp/billgo-lab/config.json <<'EOF'
{
  "name": "lab",
  "kind": "resident",
  "network": "lab",
  "listen": "0.0.0.0:8787",
  "endpoint": "https://127.0.0.1:8787",
  "data_dir": "/data",
  "allow_from": [],
  "anti_entropy_sec": 5
}
EOF

docker rm -f billgo-lab >/dev/null 2>&1 || true
docker run -d --name billgo-lab \
  -v /tmp/billgo-lab/config.json:/etc/billgo/config.json:ro \
  -v /tmp/billgo-lab/data:/data \
  billgo:dev

sleep 1
docker exec billgo-lab billgo --data /data node
docker exec billgo-lab billgo version
docker exec billgo-lab billgod -version
```

预期：

- [ ] `node` 打印 `peer_id`、`name lab`、`endpoint` 等字段
- [ ] `version` 输出 `billgo dev`
- [ ] `billgod -version` 输出 `billgod dev`

页面（容器内）：

```bash
docker exec billgo-lab sh -c 'wget -S -O /dev/null http://127.0.0.1:7878/ 2>&1 | head'
docker exec billgo-lab cat /data/billui.password
```

- [ ] 未登录访问 `/` 返回 303，指向 `/login`
- [ ] 密码文件只有一行，权限应为 0600；`docker logs` 里有同一串密码

## 2. 三节点工单闭环

清理单节点实验后重新起三个容器。

```bash
docker rm -f billgo-lab >/dev/null 2>&1 || true
docker network create billgo-manual >/dev/null 2>&1 || true
W=/tmp/billgo-manual
rm -rf "$W" && mkdir -p "$W"/{agents,data-banana,data-apple,data-peach}

cat >"$W/agents/banana.sh" <<'EOS'
#!/bin/sh
echo banana-ok > "$BILLGO_OUT_DIR/result.txt"
EOS
cat >"$W/agents/peach.sh" <<'EOS'
#!/bin/sh
if grep -Eq '"fail"[[:space:]]*:[[:space:]]*true' "$BILLGO_JOB_DIR/job.json"; then
  printf '{"reason":"not my job"}' > "$BILLGO_JOB_DIR/result.json"
  exit 1
fi
echo peach-ok > "$BILLGO_OUT_DIR/result.txt"
EOS
chmod +x "$W/agents"/*.sh
```

### 2.1 先起 banana，拿 peer_id

```bash
cat >"$W/banana.json" <<'EOF'
{
  "name": "banana",
  "kind": "resident",
  "network": "manual",
  "listen": "0.0.0.0:8787",
  "endpoint": "https://banana:8787",
  "data_dir": "/data",
  "allow_from": [],
  "bootstrap": [],
  "agent_cmd": ["/bin/sh", "/agents/banana.sh"],
  "anti_entropy_sec": 2,
  "accept_timeout_min": 5,
  "deliver_timeout_min": 5,
  "job_timeout_min": 2
}
EOF
docker rm -f banana >/dev/null 2>&1 || true
docker run -d --name banana --network billgo-manual \
  -v "$W/banana.json:/etc/billgo/config.json:ro" \
  -v "$W/data-banana:/data" -v "$W/agents:/agents:ro" \
  billgo:dev
for _ in $(seq 1 50); do docker exec banana billgo --data /data node >/dev/null 2>&1 && break; sleep 0.2; done
BANANA_ID=$(docker exec banana billgo --data /data node | awk '/^peer_id/{print $2}')
echo "BANANA_ID=$BANANA_ID"
```

- [ ] 能拿到 16 位 `BANANA_ID`

### 2.4 发起两跳工单

```bash
printf '{"task":"写一份本周周报","format":"markdown"}' >"$W/form1.json"
docker cp "$W/form1.json" apple:/tmp/form1.json
T1=$(docker exec apple billgo --data /data ticket create --form /tmp/form1.json --flow banana,peach)
echo "T1=$T1"

for _ in $(seq 1 100); do
  out=$(docker exec apple billgo --data /data ticket show "$T1" 2>/dev/null || true)
  case "$out" in *"[closed]"*) break ;; esac
  sleep 0.2
done
docker exec apple billgo --data /data ticket show "$T1"
```

- [ ] 状态是 `[closed]`
- [ ] 两跳都是 `verified`
- [ ] 事件里依次出现 `hop.sent → hop.delivered → hop.verified`，最后 `ticket.closed`

### 2.5 回执与交付物

```bash
docker exec apple sh -c "wget -qO- http://127.0.0.1:7878/api/tickets/$T1"
```

- [ ] 返回的 JSON 里 `receipts` 有两条，分别对应第 1、2 跳
- [ ] 每条都有 `blob`、`size`、`from`、`ts`

从容器里取交付物（用上一步返回的 blob 哈希）：

```bash
HASH=<把上一步的 blob 哈希粘到这里>
docker cp "apple:/data/blobs/$HASH" "$W/deliverable.bin"
cat "$W/deliverable.bin"
```

- [ ] 第 1 跳内容是 `banana-ok`
- [ ] 第 2 跳内容是 `peach-ok`

## 3. 拒绝、改派、作废

### 3.1 拒绝

```bash
printf '{"task":"做一件不会的事","fail":true}' >"$W/form2.json"
docker cp "$W/form2.json" apple:/tmp/form2.json
T2=$(docker exec apple billgo --data /data ticket create --form /tmp/form2.json --flow peach)
for _ in $(seq 1 50); do
  out=$(docker exec apple billgo --data /data ticket show "$T2" 2>/dev/null || true)
  case "$out" in *rejected*) break ;; esac
  sleep 0.2
done
docker exec apple billgo --data /data ticket show "$T2"
docker exec apple sh -c 'wget -qO- http://127.0.0.1:7878/api/status'
```

- [ ] 第 1 跳状态是 `rejected`
- [ ] `/api/status` 的 `attention` 里有 `hop_rejected`，带 `billgo ticket redispatch ...` 命令

### 3.2 改派

```bash
docker exec apple billgo --data /data ticket redispatch "$T2" --hop 1 --to banana
for _ in $(seq 1 100); do
  out=$(docker exec apple billgo --data /data ticket show "$T2" 2>/dev/null || true)
  case "$out" in *"[closed]"*) break ;; esac
  sleep 0.2
done
docker exec apple billgo --data /data ticket show "$T2"
```

- [ ] 工单变成 `[closed]`
- [ ] 第 1 跳目标变成 banana，最终 `verified`

### 3.3 作废

```bash
printf '{"task":"再拒绝一次","fail":true}' >"$W/form3.json"
docker cp "$W/form3.json" apple:/tmp/form3.json
T3=$(docker exec apple billgo --data /data ticket create --form /tmp/form3.json --flow peach)
sleep 2
docker exec apple billgo --data /data ticket void "$T3"
docker exec apple billgo --data /data ticket show "$T3"
```

- [ ] 状态变成 `[voided]`
- [ ] 之后 `billgo status` 的待处理里不再出现这张工单

## 6. 浏览器验收（宿主机）

节点配置不再带页面。另开 `billui`，密码看它的日志或 `billui.password`。

```bash
cd /Users/wanglei/code/agent/pi-docker/billgo

rm -rf "$W2" && mkdir -p "$W2/apple"
```

## 7. 常见问题

| 现象 | 先查什么 |
|---|---|
| 派单立刻被拒 | 接收方 `allow_from` 是否包含发起方 peer_id；空表示全拒 |
| 工单一直 `sent` | `docker logs <节点>`、`billgo outbox`；对方容器是否在运行 |
| `peers` 里没有对方 | bootstrap 的 `#peer_id` 是否写对；两端 `network` 是否一致 |
| 节点重启后 peer_id 变了 | `/data` 没挂卷，`identity.key` 丢了 |
| 页面打不开 | 容器是否设了 `BILLUI=0`；默认只绑容器回环，宿主机要设 `BILLUI_LISTEN` 并映射端口 |
| 启动报 socket 路径过长 | 数据目录太深，Unix socket 上限约 104 字节 |
| 工单永远不完成 | 看 `data/jobs/<ticket>-<hop>/agent.log`，以及 `agent_cmd` 是否退出 0 |
