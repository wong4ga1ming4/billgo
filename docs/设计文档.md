# Agent 之间的通信

我要创建一个agent通信的工具，去中心化

先回答什么是Agent？
Agent就是我们打的一个容器，里面有Agent的本体，就是像pi或者Claude Code等Agent的工具，还有它们附加的运营环境，还有一些必要的工具。它的一个形态就是Docker容器的一个形态，也有可能是一个镜像。所以说一个Agent它分为了两类，第一类是常驻类，就是这个容器它会一直起着，一直是活跃的。第二种是非常驻类，就是它是一个Docker Compose的一个形态，但是这但是这个容器并没有启动，你可以随时启动它，随时唤醒它。所以说你可以把它分为了常驻类，还有一个是需唤醒类。

那么再回答Agent的通信是什么？
就是当一个Agent容器去要向另一个Agent容器派发任务，这就需要通信。然后工作的这个Agent它需要提交它的交付物到这个派发任务的Agent里面去，这也是一个通信，这通信是双向的。

那再回答Agent的通信是的形态是什么？
我设计的是用工单的形式，比如发起Agent他会发起一个工单的形式。工单分为两部分内容。第一部分是工单的表单，就是他需要给下一个Agent是什么，他用表单的形式。他下一个Agent他要交付什么，他需要用表单的形式。第二个部分是工端的流转图，A Agent然后到B Agent然后到C Agent。

那么我们再回答，这个通信怎么样才能完成？或者说怎么样完成它是一个好的通信？
第一点就是需要去中心化，就是如果这个整个集群里面就只有一个Agent容器，它也可以向自己发工单。而且不同的Agent之间它是互不干扰的，就像我们人一样，就每个人都会有自己的账单。所以说工单的发起者保留工单的所有内容，但对于工单的这个任务执行者，他只提供交服务就可以了。这也是一种去中心化。第二点就是这个Agent集群彼此之间是怎么去发现的，它就需要有一个注册中心去登记。登记的东西是什么呢？就是一个Agent的一个，首先它是一个名字嘛，然后第二个是是它的描述，然后第三个是它的一个签名，就是认证信息，然后是它的分类，就是它是常驻类还是唤醒类。常驻类的话它就需要有一个那个通信地址，唤醒类的话，它就需要有一个启动方式、唤醒方式。嗯，对于常驻类，它也需要有一个唤醒方式，因为有可能这个常驻类也会掉线。

基于上面的这些内容，我们需要开发一个工具去完成这个内容。这个工具的形态呢，就需要是一个二进制包的形态，它既能充当客户端，也能充当服务端。你可以去类比一下加密货币中的那个P to P的一个协议。

这个工具三个功能：注册、发起工单、填写工单，工单管理。

首先讲一下注册，注册就需要在你注册的时候配置一个注册中心的地址。任何一个Agent都可以作为一个注册地址，你也可以去切换自己的注册地址，然后不同的注册地址里面能够发现不同的Agent集群。

所以说一般情况下就会选一个常驻的Agent去作为一个注册中心，或者是选择一个常驻的进程去作为一个注册中心。注册中心呢？它就只保留这个列表吗？第二个就是它需要去监测一下常驻的Agent是否存活（唤醒类不心跳，一直留在名单里）。大部分的Agent其实都是需唤醒类。

然后工单的存放，就是工单的发起者保留工单的所有内容，工单的中间的工作节点只负责它的交付物。

那这个工具的形态是什么呢？就是一个二进制包嘛。然后我们会把这个二进制包放到我们的Agent容器里面。

下面用三台机器说明。当前有Apple、Banana、Peach这3个Agent。
我们选择 banana 当注册中心。apple 发起工单。peach 是工单节点。

## 名录

注册中心是 banana

apple 和 peach 的配置里写 banana 的地址，以及 banana 的公钥。banana 自己也登记进这份名录，这样别人能把它选进流转图。

一条登记记录：

| 字段 | 作用 |
|---|---|
| 名称 | 组内唯一，先登记的占住 |
| 描述 | xxxx |
| 类型 | xxxx |
| 调用地址 | 发起者发这一跳时用的地址。唤醒类为空，拉起后才有 |
| 公钥 | 核对这个 agent 后来的签名 |
| 启动方式 | 唤醒类用它把容器拉起来，拉起后得到调用地址 |
| 上次心跳 | 只有常驻类有。停掉的 agent 从名单里消失；唤醒类不心跳，一直在名单里 |




## 工单

一张工单有两部分：表单，以及要经过哪些节点。apple 创建之后，表单、流转图、每一跳的交付物都写在 apple 上。

流转由 apple 推动。

1. apple 从名录里按节点的描述选出节点，写成流转图。
2. 轮到 peach 时，apple 把这一跳的表单发给 peach，并用私钥签名。peach 是唤醒类的话，apple 先按启动方式把容器拉起来、拿到调用地址，再发这一跳。
3. peach 先接受或拒绝。拒绝则回到 apple：改派别的节点还是作废整张工单，由 apple 决定——发起者持有这张工单的全部权限。
4. peach 接受后只做这一跳，把交付物签好名交回 apple。
5. apple 核对签名和内容，再派给下一跳。

peach 不保存工单，也不知道下一跳是谁。peach 只留一张回执：工单号、内容哈希、对方签名、时间。apple 也留对应的一张。回执用来证明这一跳发生过。

接活的 agent 需要有一个别人能访问的地址。只发起工单、不接活的 agent 不需要被别人连到。
